# PDF creation settings — completion summary

Status: Completed on November 8, 2026.

The Create PDF screen exposes all 28 creation options under Page layout, Image settings, and File settings. The CLI has 28 creation options; the original plan count of 30 was corrected from the actual Click metadata.

The screen uses worker metadata, typed argument arrays, read-only preflight, session drafts, reset, source folder selection, native destination dialogs, overwrite checks, and structured PDF or PNG results. Source actions use the selected folders. Front-only conflicts stay visible. Generation logs remain available after navigation.

The backend rejects crops that remove the full image, removes duplicate skip positions, and supports new PNG folders, including names with dots. Existing PDF-like image destinations still use their parent folder. Click optional defaults are converted to JSON values for metadata responses.

## Approved UX revision

The settings now use the approved light preferences modal, with category navigation, search, grouped rows, and a fixed page preview column. Save applies the draft. Cancel, Close, and Escape restore the saved values. Restoring defaults also stays in the draft until Save. The preview reads card positions and paper dimensions from worker preflight and supports front/back views and skipped positions. It is a layout diagram; image adjustments and printer offsets remain final-output operations.

Validation: 75 Node tests, 12 focused Python tests, and real Electron smoke tests passed. The Electron checks cover draft isolation, Cancel, Escape, search, field errors, preview updates, both sides, default reset cancellation, narrow layout, and PDF/PNG creation. Both source and frozen worker runs passed. The screen screenshot and guide were updated.

## Navigation speed and app theme

The Create PDF screen and its preview now load from a small bundled catalog generated by the Python engine at build time. Neither waits for the worker to start. A cold-worker Electron check measured screen and preview readiness at 180 ms, before any Python process was started. Source lists load in parallel, and thumbnails use lazy image loading and asynchronous decoding. Creation still uses worker preflight and validation.

The preferences window now uses the app's slate surfaces, gray/white accents, inherited interface font, and monospace field font. Shared theme variables come from the existing Tailwind palette. Control layout and behavior remain intact.

Verification: 76 Node tests, 13 focused Python tests, and the real Electron settings/creation smoke passed. Catalog parity with the current engine is tested; both native build scripts regenerate it. The screenshot was updated.
